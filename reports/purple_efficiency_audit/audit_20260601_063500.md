## SME Brain — Root Cause Analysis

**Ghidra decompiler platform limitation:**
Ghidra 12.1 ships a native decompiler binary for each platform. The Android
aarch64 Termux environment either lacks the `decompile/os/android_aarch64`
binary or Android's app sandbox blocks its execution (no-exec policy). This is
a platform constraint — NOT a Ghidra failure, NOT a binary failure.

Import and analysis succeeded — Ghidra fully processed the ELF, built the
function list, resolved symbols, and ran auto-analysis. Only the final
decompile-to-C rendering is blocked.

**FlameTokens 324 — significance:**
324 SAGCO-vocabulary strings are embedded in the 974K binary. This represents
the visible command surface: all the string literals, error messages, command
names, and labels compiled into the binary. This is the strings-layer (above
symbol table, below decompile). Cross-reference against 23 expected command
names confirms full command surface compiled in.

**SAGCO v2 tar.gz sealed:**
All pipeline outputs have been tar.gz + sha256sum sealed. The chain of custody
is complete at the FlameToken + analysis level even without C decompile.
